# GoldRush 2.0 因子评价与策略研究

## 一、策略体系概览

```
┌──────────────────────────────────────────────┐
│                因子评价框架                    │
│  (Factor Evaluation Framework)               │
│                                              │
│  作用：不是策略本身，而是评价策略的工具         │
│  方法：对任意策略的每轮行为计算因子值，          │
│        与收益做秩相关(IC)，找出有效因子         │
└──────────────────────────────────────────────┘
              ↓ 输出有效因子 + 权重
┌──────────┬──────────┬──────────┬──────────┐
│ 贪心策略 │ 候选评分 │ 搜索策略 │ 动态策略 │
│          │ 策略     │          │          │
└──────────┴──────────┴──────────┴──────────┘
```

其中因子不是决策方法，而是评价候选动作的打分器。

---

## 二、因子体系

### 因子定义

| 编号 | 因子名 | 含义 | 计算方式 |
|------|--------|------|----------|
| F1 | 淘金收益 | 模拟6步后捡到的金子数 | `Σ gold_collected` |
| F2 | 避雷风险 | 踩炸弹次数 | `Σ bombs_hit` |
| F3 | 探索覆盖 | 6步走过的不同格子数 | `unique_cells` |
| F4 | 敌人距离 | 与最近敌人的距离变化 | `Δdist_to_enemy` |
| F5 | NPC遭遇 | 结束位置附近NPC数 | `count(npc_dist≤2)` |
| F6 | 路径效率 | 有效移动步数/6 | `actual_moves / 6` |
| F7 | 碰撞次数 | 两角色撞到一起的次数 | `collision_count` |
| F8 | 金币差距 | 我方 vs 对手金币差 | `-(my - enemy) / 10` |
| F9 | 中心靠近 | 结束位置到中心(8,8)的距离 | `-dist_to_center` |

### 因子有效性（贪心策略 500 轮回测）

| 因子 | IC | 有效性 | 结论 |
|------|-----|--------|------|
| F1 淘金 | 1.00 | — | 目标变量 |
| **F9 中心靠近** | **0.55** | **强** | 中心金多，靠近中心是核心 |
| F3 探索覆盖 | 0.19 | 弱 | 多走几步有好处 |
| F2 避雷 | 0.08 | 噪音 | 贪心策略本身会避雷 |
| F4 敌人距离 | -0.08 | 噪音 | 暂时看不出影响 |
| F5~F8 | <0.1 | 噪音 | 需更多数据验证 |

### 评分公式

```
Score(候选动作) = w1×F1 + w2×F2 + ... + w9×F9
```

当前权重（基于 IC）：

```
w = [1.0, -0.08, 0.19, -0.08, 0.08, 0.08, 0.08, 0.08, 0.55]
     F1    F2    F3    F4    F5    F6    F7    F8    F9
```

---


>在上述评价体系下，若不计算力和时间，我们可以枚举所有可能的走法，选择评分最高的走法作为策略。但由于时间有要求，我们需要先给出一些候选策略，再利用上述因子评价体系对候选策略进行评分，选择评分最高的策略作为最终策略。
## 三、策略方向

### 策略 1: 贪心策略 (Greedy Strategy)

**思路**: 每个角色独立向最近的可见金子直线移动

```
for 角色 in [0, 1]:
  找到最近的可见金子
  每步向金子方向移动
```

**特点**: 极简，0ms 延迟，但容易踩炸弹、路径低效
**平均金币**: ~200/50轮
**适用**: baseline 参考

---

### 策略 2: 启发式候选策略 (Heuristic Candidate Strategy) ← 下一步

**思路**: 用有意义的启发式动作代替随机候选

| 候选名 | 逻辑 | 适用场景 |
|--------|------|----------|
| 贪心淘金 | 向最近金子移动 | 默认 |
| 避雷淘金 | 向金子移动，绕开炸弹 | 炸弹密集区 |
| 中心集结 | 向中心(8,8)移动 | F8权重高时 |
| 抢金模式 | 向敌人方向靠近 | 敌人附近有金 |
| NPC跟随 | 向最近NPC移动 | NPC有交互时 |

**优势**: 只需 5-6 个候选，延迟 0.003ms，且每个候选都有逻辑

---

### 策略 3: 束搜索策略 (Beam Search Strategy) ← 中期

**思路**: 将 6 步分解为 6 个阶段，每阶段保留 top-K 局部最优

```
Beam = {空序列}, 束宽=10
for step = 1 to 6:
  for seq in Beam:
    for action in [上,下,左,右,不动]:
      新序列 = seq + action
      计算 Score(新序列)
  Beam = top-10 新序列
返回 Beam 中 Score 最高的序列
```

**优势**: 保证找到 6 步之间的最优组合，不会遗漏"单步差但整体优"的序列
**计算量**: 6 × 10 × 5 = 300 次评分
**延迟预估**: 0.01ms/轮

---

### 策略 4: 动态权重策略 (Dynamic Weight Strategy) ← 长期

**思路**: 权重 w 不是固定的，而是随游戏阶段变化

| 阶段 | F1 淘金 | F8 中心 | 逻辑 |
|------|---------|---------|------|
| 早期(0-100) | 高 | 高 | 金多，优先淘金+占中心 |
| 中期(100-300) | 中 | 中 | 金子少了，需要效率 |
| 晚期(300-500) | 低 | 低 | 快结束，金子少了 |

**实现方式**:
```
w(stage) = w_early   if round < 100
         = w_mid     if round < 300
         = w_late    otherwise
```

---

### 策略 5: 回测优化策略 (Backtest-Optimized Strategy) ← 终极

**思路**: 用批量回测自动搜索最优权重

```
# 训练
for 权重组合 in 参数空间:
  for seed in 训练集(50个):
    跑500轮 → 记录总金币
  平均金币 = 总金币 / 50
最优权重 = argmax(平均金币)

# 验证
用最优权重在验证集(20个新seed)上测试
```

**搜索方法**:
- 网格搜索：暴力枚举，适合低维（2-3个参数）
- 贝叶斯优化：适合中等维度（5-10个参数）
- 遗传算法：适合高维（10+个参数）

---
> 目前的`sim --demo`用1，2，3来分别演示随机走，贪心走，和随机生成一堆之后的评分走

## 四、研究路线图
总结上述的优化方向，主要分为两类
- 因子评价体系的完善，实现动态权重或者找到最优权重
- 策略的优化：为因子评价体系给出尽量少的目标，
  以便在有限时间内找到最优策略

```
Phase 1 (当前) ✅
  贪心策略 → 因子评价策略
  回测系统 → 因子IC分析
  发现: F9中心靠近 IC=0.55

Phase 2 (下一步)
  启发式候选策略: 5-6个有意义的候选
  目标: 性能不降，延迟降到 0.003ms

Phase 3
  束搜索策略: 6步联合优化
  目标: 比启发式再提升 20%

Phase 4
  动态权重: 分阶段调整权重
  目标: 晚期表现提升

Phase 5
  回测优化: 自动搜索最优权重
  目标: 找到全局最优参数
```
